## 详细分析

### 1. 实时QPS

#### 指标说明
显示最近1秒内的查询吞吐量

#### 计算公式
```
实时QPS = deltaRows = 当前总数据行数 - 上次采样时总数据行数
```

#### 数据来源
- **主代码**: `StatsCollector.java:528-529`
- **调用**: `sampleAndMaybePrint() 方法`
- **变量**:
  - `lastTotalRows` - 上次采样时的总行数 (L98)
  - `deltaRows` - 本次采样的增量行数 (L528)

#### 打印位置
`StatsCollector.java:592`

#### 准确性分析
✅ **基本准确**，这是对最近1秒数据的简单计数

#### 示例数值
用户输出中显示为 **5.5万**

### 3. QPS[30s/1m/5m/10m] - 多时间窗口QPS

#### 指标说明
显示不同时间窗口内的平均查询吞吐量

#### 计算公式

**情况1：窗口时间 < 设置的窗口大小 (实际样本数 < 窗口大小)**
```
QPS = 总数据行数 / (当前时间 - 程序开始时间)
```

**情况2：窗口时间 >= 设置的窗口大小**
```
QPS = 窗口内总数据行数 / 窗口时间
窗口时间 = max(最后采样时间戳 - 最早采样时间戳, 实际样本数)
```

#### 数据来源
- **主代码**: `StatsCollector.java:663-694`
- **循环缓冲区**:
  - `sampleTimestamps[]` - 采样时间戳数组 (L76)
  - `deltaTotalRows[]` - 每秒钟增量行数 (L77)
  - `sampleIndex` - 当前写入位置 (L90)

#### 打印位置
`StatsCollector.java:414-415, 595-596`

#### 准确性分析
⚠️ **有改进空间**

**问题分析**：
1. 当实际样本数 < 窗口大小时，直接使用平均QPS的计算方式，导致各个窗口显示相同的值
2. 窗口时间计算的下限为0.1秒，可能导致QPS虚高
3. 使用固定样本数，而不是基于实际时间戳计算窗口

#### 示例数值
用户输出：**2.7万/2.8万/3.7万/3.7万**

## 发现的问题

### 问题1：按表统计全部显示为0 ⭐⭐⭐⭐⭐ (严重)

#### 症状
- 总体统计显示 5,939,865 行
- 但按表统计全部为0
- 窗口内表TPS也为0

#### 可能原因

**原因1：测试代码没有调用 recordTableWrite()**
```java
// 只调用了 recordBatch()，没有调用 recordTableWrite()
StatsCollector.getInstance().recordBatch(batches, rows, nanos);
// 缺少这行：
// StatsCollector.getInstance().recordTableWrite(tableName, rows, nanos);
```

**原因2：reset() 方法可能在中间被调用**
```java
// reset() 会清空所有统计
StatsCollector.getInstance().reset();
```

#### 建议检查
1. 检查测试代码中是否调用了 `recordTableWrite()`
2. 检查是否有中间调用了 `reset()`
3. 检查表名是否匹配 ("buyer_info", "order_main", "order_item")

---

### 问题2：写入总耗时计算不正确 ⭐⭐⭐ (中等)

#### 位置
`StatsCollector.java:813`

#### 问题代码
```java
totalBatchesInWindow += 1;  // ❌ 错误：每秒钟只计数1
```

#### 应该改为
```java
totalBatchesInWindow += deltaBatchCount[idx];  // ✅ 正确：使用实际记录的批次数
```

#### 影响
- 窗口内批次数统计不准确
- 平均延迟计算有偏差

---

### 问题3：多时间窗口QPS在样本不足时显示相同值 ⭐⭐ (低)

#### 位置
`StatsCollector.java:672-678`

#### 问题
当实际样本数 < 窗口大小时，所有窗口都使用相同的计算方式（从开始到现在的平均QPS），导致：
- QPS[30s/1m/5m/10m] 显示非常相似的值
- 无法区分不同时间窗口的真实情况

#### 建议
改为：
1. 当样本不足时，显示"数据不足"
2. 或者使用实际样本数计算，而不是从开始到现在的总平均

---

### 问题4：缺少deltaTableNanos和deltaTableRetries数组

#### 问题
只有 `deltaTableRows` 数组记录各表每秒增量行数，但没有：
- `deltaTableNanos` - 各表每秒增量纳秒数
- `deltaTableRetries` - 各表每秒增量重试次数

因此无法计算各表的窗口内延迟统计。

### 建议3：改进多时间窗口QPS计算

**修改逻辑**:
- 当实际样本数少于窗口大小时，使用实际样本数计算
- 但显示时标注"窗口未填满"
- 不要直接使用总平均QPS

---

### 建议4：添加统计数据一致性检查

**添加方法**:
```java
public boolean validateStats() {
    long totalFromTables = 0;
    for (AtomicLong count : tableRows.values()) {
        totalFromTables += count.get();
    }
    long totalRows = this.totalRows.get();
    return totalFromTables <= totalRows;
}
```
